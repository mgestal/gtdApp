🚀 Instalación y despliegue

Cómo ejecutar GTD App en tu propio servidor o máquina.

🐳 Docker (Recomendado)
La opción más sencilla y portable para instalar en cualquier equipo.
Requisitos: Docker y Docker Compose instalados en tu sistema.
1. Clonar el repositorio
git clone <tu-repositorio> cd gtdApp
2. Iniciar la aplicación
docker-compose up -d
Esto descargará las imágenes, creará los contenedores, ejecutará el esquema SQL automáticamente y arrancará la app.
Acceder a la app
http://localhost:5000
✓ La base de datos está lista automáticamente
Comandos útiles
Ver logs: docker-compose logs -f app
Parar: docker-compose down
Borrar BD: docker-compose down -v
✓ Ventajas
  • Idéntico en cualquier máquina
  • BD incluida automáticamente
  • Sin conflictos de dependencias
  • Fácil de actualizar
⚠ Requisitos
  • Docker instalado
  • ~2GB de espacio (imágenes)
  • Puertos 5000 y 3306 libres
🛠 Instalación manual (Avanzado)
Para usuarios que prefieren tener acceso directo a los componentes.
Requisitos: Python 3.10+, MySQL/MariaDB, pip, git
1. Clonar y crear entorno virtual
git clone <tu-repositorio> cd gtdApp python -m venv .venv source .venv/bin/activate # En Windows: .venv\Scripts\activate
2. Instalar dependencias
pip install -r requirements.txt
3. Crear la base de datos
mysql -u root -p <<'SQL' CREATE DATABASE gtd CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; CREATE USER 'gtd'@'localhost' IDENTIFIED BY 'gtd_password'; GRANT ALL PRIVILEGES ON gtd.* TO 'gtd'@'localhost'; FLUSH PRIVILEGES; SQL mysql -u gtd -p gtd < sql/esquema.sql
4. Configurar instance/config.json
Crea o edita el archivo con tus datos de BD (usuario, contraseña, timezone, etc.). Ver Configuración más abajo.
5. Ejecutar la app
python app.py
Desarrollo: acceder a http://localhost:5000
6. Configurar Apache + mod_wsgi (opcional para producción)
Si publicas la app con Apache en la ruta /gtdApp, puedes usar una configuración como esta en webconfig/000-default.conf (HTTP) y webconfig/apps-SSL.conf (HTTPS).
# ------------------------- # GTD App (HTTP - 000-default.conf) # ------------------------- WSGIDaemonProcess gtdApp user=www-data group=www-data threads=5 \ python-home=/var/www/gtdApp/.venv \ python-path=/var/www/gtdApp WSGIScriptAlias /gtdApp /var/www/gtdApp/wsgi.py process-group=gtdApp application-group=%{GLOBAL} SetEnv GTD_ADMIN_PASSWORD "N03m1t4" SetEnv GTD_SECRET_KEY "1234567890" Alias /gtdApp/static /var/www/gtdApp/static <Directory /var/www/gtdApp> AuthType Basic AuthName "Restricted Content" AuthUserFile /etc/apache2/htpasswd-apacheusers Require valid-user Options FollowSymLinks </Directory> <Directory /var/www/gtdApp/static> AuthType Basic AuthName "Restricted Content" AuthUserFile /etc/apache2/htpasswd-apacheusers Require valid-user Options FollowSymLinks </Directory> # ======================== # GTD App (SSL - apps-SSL.conf) # ======================== WSGIDaemonProcess gtdAppSSL user=www-data group=www-data threads=5 \ python-home=/var/www/gtdApp/.venv \ python-path=/var/www/gtdApp WSGIScriptAlias /gtdApp /var/www/gtdApp/wsgi.py process-group=gtdAppSSL application-group=%{GLOBAL} Alias /gtdApp/static /var/www/gtdApp/static <Directory /var/www/gtdApp> AuthType Basic AuthName "Restricted Content" AuthUserFile /etc/apache2/htpasswd-apacheusers Require valid-user Options FollowSymLinks </Directory> <Directory /var/www/gtdApp/static> AuthType Basic AuthName "Restricted Content" AuthUserFile /etc/apache2/htpasswd-apacheusers Require valid-user Options FollowSymLinks </Directory> SetEnv GTD_ADMIN_PASSWORD "gtd_password" SetEnv GTD_SECRET_KEY "1234567890"
# Activar módulos/sitios y recargar Apache sudo a2enmod wsgi sudo a2enmod ssl sudo a2ensite 000-default sudo a2ensite apps-SSL sudo systemctl reload apache2
Recomendación: mueve las credenciales reales a variables de entorno del sistema o a un fichero protegido y evita dejarlas hardcodeadas en los vhost.
✓ Ventajas
  • Control total
  • Debugging local
  • Personalización avanzada
⚠ Desventajas
  • Más configuración manual
  • Conflictos de dependencias posibles
  • Portabilidad limitada
🌐 Producción (Servidor remoto)
Ejecutar en un VPS, Raspberry Pi, NAS o servidor propio.
Recomendado: Usar Docker en el servidor para mantener consistencia con desarrollo.
En VPS/Servidor Linux
# SSH al servidor ssh usuario@tu-servidor.com # Clonar repo, instalar Docker si no está sudo apt update && sudo apt install docker.io docker-compose sudo usermod -aG docker $USER # Clonar y ejecutar git clone <tu-repositorio> cd gtdApp docker-compose up -d # Para acceso remoto seguro, usar reverse proxy (nginx + SSL)
Opciones de acceso:
Opción 1: Port forwarding (acceso a IP:5000 desde la red local o internet)
Opción 2: Nginx reverse proxy + SSL (recomendado para internet)
Opción 3: Apache + mod_wsgi (si tienes Apache ya instalado)
Automatizar backups
# Backup diario (añadir a crontab) 0 2 * * * docker exec gtd_mysql mysqldump -u gtd -pgtd_password gtd > /backups/gtd_$(date +\%Y\%m\%d).sql
⚙️ Configuración (instance/config.json)
Parámetros principales de la aplicación.
{ "db": { "host": "127.0.0.1", // localhost o 'mysql' si usas Docker "port": 3306, "user": "gtd", "password": "gtd_password", "database": "gtd", "charset": "utf8mb4" }, "app": { "timezone": "Europe/Madrid", // Tu zona horaria "title": "GTD App", "calendar_sync": { "calendar_id": "primary" // 'primary' o email@gmail.com } }, "security": { "allowed_user_ids": [835990144, 1228759930], // IDs Telegram permitidos "allowed_group_ids": [], "reply_on_unauthorized": true } }
Parámetros importantes:
  • timezone: Zona horaria para mostrar fechas correctamente
  • calendar_id: "primary" para tu calendario por defecto o email para compartido
  • allowed_user_ids: Solo estos usuarios Telegram pueden usar el bot
🔐 Credenciales Google (Gmail + Calendar)
Configurar acceso a Gmail y Google Calendar.
Necesario para importar correos y eventos automáticamente.
1. Google Cloud Console
• Ir a console.cloud.google.com
• Crear un nuevo proyecto
• Habilitar APIs: Gmail y Google Calendar
• Crear OAuth 2.0 Client (tipo "Aplicación de escritorio")
2. Guardar credenciales
# Descargar JSON y guardar como: instance/gmail_credentials.json # Se generará automáticamente: instance/gmail_token.json
🔧 Solución de problemas
Errores comunes y cómo resolverlos.
Error de conexión a BD
• Docker: Verificar que el contenedor MySQL está corriendo: docker-compose logs mysql
• Manual: Asegurar que MySQL está ejecutándose y credentials en config.json son correctas

Puerto 5000 en uso
• Docker: Cambiar puerto en docker-compose.yml: "5001:5000"
• Manual: Usar export FLASK_ENV=production; python app.py --port 8000

Permisos en Docker
• Agregar usuario a grupo: sudo usermod -aG docker $USER

Pérdida de datos al bajar contenedor
• Los volúmenes persisten: docker-compose down (sin -v)
